# 2026-08-14 — Claude Code support

## Summary

Made the skill suite installable on Claude Code without giving up Codex
support. One `skills/<name>/SKILL.md` source now feeds both agents: Claude Code
loads it as the `resumable-project` plugin, Codex receives a copy from
`scripts/install.sh`.

## What changed

- Moved the three skill directories under `skills/`, the directory a Claude
  Code plugin scans by default. Codex is unaffected because the installer
  copies by directory name into `~/.codex/skills`.
- Added `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`
  describing the `resumable-project` plugin in the `whalesalad-skills`
  marketplace, sourced from the repository root.
- Added `CLAUDE.md` importing `@AGENTS.md`, since Claude Code does not read
  `AGENTS.md`. Claude-specific notes sit below the import.
- Rewrote `scripts/install.sh` to take `--codex`, `--claude`, and `--all`, and
  to discover skills from `skills/` instead of a hardcoded list. With no flags
  it installs into whichever agent homes already exist and creates none.
- Added `scripts/validate_skills.py`: dependency-free structural validation of
  frontmatter, naming, size, Codex UI metadata, and manifest agreement. This
  lets a contributor with only Claude Code installed validate the repository.
- Made `check.sh` treat the Codex validator as optional rather than required,
  and run it over the new paths.
- Generalized the skill bodies from `AGENTS.md` to agent instruction files in
  general, and taught `bootstrap-resumable-project` to bridge `AGENTS.md` to
  `CLAUDE.md` with an `@AGENTS.md` import rather than duplicating guidance.

## Decisions

- One bundled plugin rather than three single-skill plugins. The three skills
  compose by design, and one install command is the point of the exercise.
  Splitting later is possible with per-entry `skills` paths.
- Marketplace source `"./"`, so the repository root is the plugin. This keeps a
  single `skills/` tree serving both agents. The cost is that contributor files
  ship in the plugin cache, which is harmless.
- Frontmatter stays inside the six Agent Skills spec fields. Claude Code accepts
  more, but claude.ai uploads and the Skills API reject extras, and the
  restriction costs nothing today.
- Copy semantics retained for `install.sh`. Symlinking would make every session
  track the working tree, which the original design deliberately avoided.

## Validation

```sh
./scripts/check.sh
```

Observed: the portable validator passed 3 skills and both manifests, the Codex
`quick_validate.py` reported `Skill is valid!` three times, placeholder and
private-path scans passed, and shell syntax checks passed.

```sh
CODEX_HOME=<sandbox>/codex CLAUDE_CONFIG_DIR=<sandbox>/claude \
  ./scripts/install.sh --all
```

Observed: all three skills installed into both sandbox homes with
`SKILL.md` and `agents/openai.yaml` intact. Sandbox removed afterward.

```sh
claude plugin validate .claude-plugin/marketplace.json   # passed
claude plugin validate .claude-plugin/plugin.json        # passed with 1 warning
claude plugin marketplace add ./
claude plugin install resumable-project@whalesalad-skills
claude plugin details resumable-project
```

Observed: install succeeded at user scope, and the component inventory listed
all three skills at roughly 389 always-on tokens.

The plugin.json warning is expected: `CLAUDE.md` at the plugin root is not
loaded as plugin context. It is contributor guidance that happens to sit inside
the plugin source, not content intended for plugin users.
