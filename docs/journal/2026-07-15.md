# 2026-07-15 — Resumable project skill suite

## Summary

Established the public source workspace for three composable Codex skills:

- `track-project-journal`
- `manage-project-todo`
- `bootstrap-resumable-project`

The suite separates narrative evidence from prioritized current state, then
composes both practices when scaffolding or upgrading a repository. Existing
repository conventions take precedence over the fallback layout.

## What changed

- Wrote and committed the approved design and public-safe provenance.
- Initialized all three packages with the system skill scaffolder.
- Replaced generated placeholders with concise workflow-based instructions.
- Added matching UI metadata under each skill's `agents/openai.yaml`.
- Added repository guidance, TODO and journal conventions, an MIT license, and
  repeatable check and install scripts.
- Installed reviewed copies under the global Codex skills directory.

## Decisions

- Keep journaling and TODO management independent so either can be requested
  without surprising changes to the other artifact.
- Make the bootstrap skill load the sibling skills instead of copying their
  detailed rules. This reduces behavioral drift.
- Copy reviewed source into the global installation rather than symlinking it.
  Experimental branches therefore do not immediately alter every Codex session.
- Publish only generic provenance. Source repository names, operational details,
  infrastructure identifiers, credentials, costs, and private artifacts stay
  outside this repository.

## Validation


Observed: all three skill packages passed the structural validator, generated
placeholder scanning passed, the public-path/network-identifier scan passed,
shell syntax checks passed, and Git whitespace validation passed.

```sh
./scripts/install.sh
```

Observed: all three skills installed successfully. Recursive source-to-install
comparisons produced no differences, and each installed copy passed structural
validation.

The behavior contract was reviewed against the approved scenario set:

| Scenario | Expected handling |
|---|---|
| Blank repository | Add only known state plus the minimal continuity files |
| Existing repo without tracking | Patch missing connections without inventing history |
| Existing canonical pattern | Preserve its established structure |
| Custom journal or tracker path | Follow local instructions instead of fallback paths |
| Multiple sessions on one date | Append without overwriting earlier content |
| Large standalone topic | Use a short dated topic breakout |
| Conflicting local instructions | Let the local repository contract win |
